# HiFi Op-Amp Legends Map

The audio op-amp ICs that Hi-Fi and DIY-audio enthusiasts rate most highly, organised as one short page per family. Each page covers:

- why the part is rated and what to watch out for;
- whether the silicon changed while the part number stayed the same;
- the timeline of datasheet revisions, each linked to the best surviving copy.

**Why revisions matter.** A part number does not guarantee a particular die. Since 2022, Texas Instruments has been moving legacy analog parts to new fabs and new dies. Today's NE5532, OPA2134 or TL072 is not always the chip that earned its reputation.

These are the die redesigns recorded with medium or high confidence. The full register is in [docs/REVISION-HAZARDS.md](docs/REVISION-HAZARDS.md); it also covers fab moves, second-source differences and datasheet respecs.

## Datasheets

[docs/DATASHEETS.md](docs/DATASHEETS.md) shows each datasheet document's known revisions, oldest first, linked to the best copy. Distributor and archive copies often preserve revisions the vendor no longer serves. Every record is also in `data/datasheets.csv`.

To download the PDFs, including every historical revision the Internet Archive holds:

```bash
pip install pypdf                                       # optional: reads the revision printed on each PDF
python tools/fetch_datasheets.py --dry-run              # show every URL and archive query
python tools/fetch_datasheets.py --family NE5532 OPAx134
python tools/reconcile_datasheets.py                    # write PDF-confirmed revisions back into the data
```

The fetcher tries every recorded URL, falling back to its Internet Archive copy. It also probes TI's lettered revisions (`ti.com/lit/ds/slos075j/…`) and queries the Internet Archive for every current and legacy vendor datasheet location (TI, Burr-Brown, National, ADI, Linear, JRC/Nisshinbo, Philips/NXP, onsemi/Motorola, ST, Fairchild). `datasheets/INDEX.md` lists the results in date order.

You can also do all of this on GitHub: **Actions → Fetch datasheets → Run workflow**. It fetches, writes the confirmed revisions back into the data, regenerates the docs and commits them. PDFs are uploaded as a workflow artifact, not committed. Datasheets remain the copyright of their publishers.

## Repository layout

| Path | What it is |
|---|---|
| `data/families/<id>.json` | The dataset, one file per die family (source of truth) |
| `data/meta.json` | Schema version and candidates considered but not included |
| `docs/families/<id>.md`, `docs/*.md` | Generated pages ([METHOD.md](docs/METHOD.md) is hand-written) |
| `tools/build_docs.py` | Regenerates every generated page and `data/datasheets.csv` |
| `tools/fetch_datasheets.py`, `tools/reconcile_datasheets.py` | Download datasheets and confirm revisions from the PDFs |
| `tools/schema.py`, `tools/validate_rewrite.py` | Field rules and length caps; checks that an edit keeps every URL, PCN and document number |
| `tests/` | Offline tests for the tools, the data and the generated docs |

To contribute, edit a family file, then run `python tools/build_docs.py` and `python -m unittest discover -s tests`, and open a PR with sources. Sound descriptors are community opinion, not measurements. Every silicon change carries a confidence level and sources. [docs/METHOD.md](docs/METHOD.md) explains how the data was gathered and its limits.
